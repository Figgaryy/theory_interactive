1. เซต (Sets)

1.1 นิยามพื้นฐาน · ∈ กับ ⊆ · ∅ กับ {∅}

นิยาม เซต = กลุ่มของสมาชิก (ไม่สนลำดับ ไม่สนซ้ำ). x ∈ A = x เป็นสมาชิกของ A. A ⊆ B = ทุกสมาชิกของ A เป็นสมาชิกของ B (subset). A = B ⇔ A ⊆ B และ B ⊆ A. A ⊂ B (proper subset) = A ⊆ B และ A ≠ B. ∅ = เซตว่าง ไม่มีสมาชิก. |A| = จำนวนสมาชิก.

ภาษาคน: คิดว่าเซตคือ "กล่อง" — ∈ ถามว่า "ของชิ้นนี้อยู่ในกล่องไหม" ส่วน ⊆ ถามว่า "ของทุกชิ้นในกล่อง A อยู่ในกล่อง B ด้วยไหม". กล่องเปล่า (∅) กับกล่องที่มีกล่องเปล่าอยู่ข้างใน ({∅}) เป็นคนละอย่าง — อันแรกมี 0 ชิ้น อันหลังมี 1 ชิ้น.

1.4 Partition

นิยาม Π เป็น partition ของ A ⇔ Π เป็นเซตของ subset ของ A ที่ (1) ทุกบล็อกไม่ว่าง (2) บล็อกไม่ซ้อนกัน (pairwise disjoint) (3) รวมทุกบล็อกได้ A.

ภาษาคน: หั่น A เป็นกอง ๆ ทุกชิ้นอยู่กองเดียว ไม่มีกองเปล่า. ขนาดของ partition = จำนวนกอง: อย่างน้อย 1 ({A}) อย่างมาก |A| (ทุกตัวอยู่เดี่ยว). จำนวน partition ของ A (Bell number): |A|=1 → 1, |A|=2 → 2 ({{a,b}}, {{a},{b}}), |A|=3 → 5 ({{a,b,c}}, {{a},{b,c}}, {{b},{a,c}}, {{c},{a,b}}, {{a},{b},{c}}) — ชุด 3 ข้อ 1(d)(e), ชุด 4 ข้อ 5.2/6.1. partition ↔ equivalence relation แบบหนึ่งต่อหนึ่ง (§2.4).

2. ความสัมพันธ์ (Relations)

2.1 คู่อันดับ · ผลคูณคาร์ทีเซียน · relation · inverse · composition

(a,b) คู่อันดับ (ลำดับสำคัญ: (a,b) ≠ (b,a)). A × B = {(a,b) | a ∈ A, b ∈ B}, |A×B| = |A|·|B|. binary relation จาก A ไป B = subset ใด ๆ ของ A × B (relation บน A = subset ของ A × A). R⁻¹ = {(b,a) | (a,b) ∈ R}. Q ∘ R = {(a,c) | ∃b: (a,b) ∈ Q และ (b,c) ∈ R} ("เดินตาม Q หนึ่งก้าว แล้วตาม R อีกก้าว").

ภาษาคน: วาด relation เป็นกราฟลูกศร a → b. R⁻¹ = กลับหัวลูกศรทุกเส้น (จำนวนเท่าเดิม). R ∘ R = ทางเดิน 2 ก้าว: (x,z) อยู่ใน R∘R ถ้ามี y ที่ x→y→z (self-loop นับด้วย: b→b→c ให้ (b,c), b→b→b ให้ (b,b)). R ∘ R⁻¹ = ไป 1 ก้าวแล้วย้อน 1 ก้าว = คู่ (x,z) ที่ "ชี้ไปที่ y เดียวกัน" — x ทุกตัวที่มีลูกศรออกจะได้ (x,x). 2R คือ power set ของเซตของคู่ → 2|R|. (ชุด 2 ข้อ 2, ชุด 3 ข้อ 2)

กับดัก: R ∘ R ไม่ได้มี R เดิมอยู่ข้างใน — ต้องเป็นทางเดิน 2 ก้าวเท่านั้น (เฉลยต้นฉบับชุด 2 ข้อ 2b และชุด 3 ข้อ 2a นับผิดตรงนี้). ถ้า A × B = ∅ (เช่น B = ∅) relation เดียวที่มีคือ ∅ ขนาด 0 (ชุด 4 ข้อ 6.3).

2.2 คุณสมบัติ: reflexive / symmetric / antisymmetric / transitive

คุณสมบัติ (R บน A)นิยามทางการภาษาคน / ในกราฟเท็จเมื่อ
reflexive∀a∈A: (a,a) ∈ Rทุกจุดมี self-loopมี a สักตัวที่ไม่มี (a,a)
symmetric(a,b)∈R ⇒ (b,a)∈Rลูกศรไปกลับเป็นคู่เสมอมี a→b แต่ไม่มี b→a
antisymmetric(a,b)∈R และ (b,a)∈R ⇒ a = bห้ามมีลูกศรสองทางระหว่างจุดต่างกัน (self-loop ได้)มี a→b และ b→a โดย a ≠ b
transitive(a,b),(b,c)∈R ⇒ (a,c)∈Rต่อกัน 2 ก้าวได้ ต้องมีทางลัด 1 ก้าวมี a→b→c แต่ไม่มี a→c (รวม a→b→a ต้องมี a→a)
equivalence relation = reflexive + symmetric + transitive (แบ่ง A เป็น partition ของ equivalence class). partial order = reflexive + antisymmetric + transitive. total order = partial order ที่ทุกคู่เทียบกันได้ ((a,b)∈R หรือ (b,a)∈R).

ตัวอย่างต้องรู้:

  • relation ว่าง R = ∅ บน A ≠ ∅: symmetric ✓ antisymmetric ✓ transitive ✓ (นิยามเป็นรูป "ถ้า…แล้ว…" ไม่มีกรณีให้ตรวจ = จริงโดยว่างเปล่า) แต่ reflexive ✗ (ต้องการ (a,a) จริง ๆ) → ไม่ใช่ partial order. (ชุด 1 ข้อ 3, ชุด 4 ข้อ 7.1)
  • R = A × A: ครบทุกคู่ → equivalence relation; ไม่ antisymmetric ((a,b),(b,a) ทั้งคู่) → ไม่ใช่ partial order (ชุด 4 ข้อ 7.2)
  • ≤ บน ℕ: partial order และ total order. <: ไม่ reflexive (strict order). ⊆ บนเซต: partial order แต่ไม่ total ({1} กับ {2} เทียบไม่ได้)
  • "mother of": ไม่ symmetric, antisymmetric ✓ (ไม่มีคู่สองทาง). "sibling of": symmetric ✓ ไม่ antisymmetric. "ancestor of": transitive ✓ ไม่ reflexive → ไม่ใช่ partial order (ชุด 3 ข้อ 3)
  • R = {((m,n),(p,q)) | m·q ≥ n·p} = "m/n ≥ p/q": reflexive ✓ transitive ✓ symmetric ✗ antisymmetric ✗ ((1,1) กับ (2,2) เทียบเท่ากันแต่คนละตัว) → ไม่ใช่ partial/total order (ชุด 2 ข้อ 3)
  • R′ = {(a,b)∈R | (b,a)∉R} ("ส่วนเคร่งครัด" ของ R transitive): ไม่ reflexive, transitive, antisymmetric (ชุด 4 ข้อ 9.4)
  • reflexive บน ℕ บังคับให้มี (n,n) ทุก n → R อนันต์ (ชุด 4 ข้อ 6.4)
กับดัก: symmetric กับ antisymmetric ไม่ใช่ตรงข้ามกัน — relation ว่าง และ {(a,a)} เป็นทั้งสองอย่าง. "มี self-loop บ้าง" ไม่พอสำหรับ reflexive ต้องครบทุกตัวในเซตฐาน. ตรวจ transitive อย่างเป็นระบบ: หาทุกคู่ (x,y),(y,z) ที่ตัวกลางตรงกัน (รวม y = x หรือ z) แล้วเช็ค (x,z).

2.3 Closure ของ relation

นิยาม reflexive (transitive, …) closure ของ R = relation ที่เล็กที่สุด (ตาม ⊆) ที่มี R เป็น subset และมีคุณสมบัตินั้น.
  • reflexive closure = R ∪ {(a,a) | a ∈ A} — เติม self-loop ที่ขาดทุกจุด
  • transitive closure R⁺ = เติมทางลัดจนครบ: ทำเป็นรอบ — หา (x,y),(y,z) ที่ยังไม่มี (x,z) → เติม → ตรวจซ้ำ (คู่ที่เพิ่งเติมอาจสร้างคู่ใหม่) จนไม่มีอะไรเพิ่ม. มุมกราฟ: (x,z) ∈ R⁺ ⇔ มีทางเดินจาก x ไป z ยาว ≥ 1
  • reflexive transitive closure R* = R⁺ ∪ self-loop ทั้งหมด = "ไปถึงได้ด้วยทางเดินยาว ≥ 0"

ตัวอย่าง (ชุด 1 ข้อ 5): A={a,b,c}, R={(a,a),(a,b),(b,c),(c,a)} → reflexive closure = R ∪ {(b,b),(c,c)}; กราฟมี cycle a→b→c→a ทุกจุดถึงทุกจุด → reflexive-transitive closure = A × A ทั้ง 9 คู่. (ชุด 3 ข้อ 2): R={(a,b),(b,c),(a,d),(b,b)} → เติม (a,a),(c,c),(d,d) แล้ว transitive เติมแค่ (a,c) (a→b→c).

กับดัก: คำว่า smallest — ห้ามเติมเกินจำเป็น; และห้ามลืมรอบที่สองของ transitive.

2.4 Row set · Diagonal set · Diagonalization principle

R ⊆ A × A. row set ของ a: Ra = {x ∈ A | (a,x) ∈ R} (แถว a ในตาราง). diagonal set D = {x ∈ A | (x,x) ∉ R} (ตำแหน่งบนเส้นทแยงที่ว่าง). Diagonalization principle: D ≠ Ra สำหรับทุก a ∈ A.

ทำไมจริง: D กับ Ra ต่างกันที่สมาชิก a เสมอ: a ∈ D ⇔ (a,a) ∉ R ⇔ a ∉ Ra. ใช้ทำอะไร: พิสูจน์ว่า 2ℕ นับไม่ได้ (ถ้าเรียง subset ทั้งหมดเป็นแถวได้ D จะเป็น subset ที่ไม่อยู่ในแถวไหนเลย — ขัดแย้ง) → มีเซตอนันต์ที่ใหญ่กว่า ℕ. ตัวอย่าง: R={(n,n+1)}: เส้นทแยงว่างทั้งเส้น → D = ℕ, R0 = {1} (ชุด 1 ข้อ 8). R={(a,a),(b,b),(c,c),(d,d)}: เส้นทแยงเต็ม → D = ∅, Ra = {a} (ชุด 4 ข้อ 8.1–8.2). ข้อความของหลักการต้องใช้คำว่า always different (ชุด 4 ข้อ 8.3).

3. ฟังก์ชัน (Functions)

นิยาม f : A → B เป็นฟังก์ชัน ⇔ f ⊆ A × B (เป็น relation!) และทุก a ∈ A มีคู่ (a,b) ∈ f เพียงคู่เดียว. A = domain, B = co-domain. one-to-one (injective): a ≠ a′ ⇒ f(a) ≠ f(a′). onto B (surjective): ทุก b ∈ B มี a ที่ f(a) = b. bijection: ทั้งสองอย่าง.

ภาษาคน: ฟังก์ชัน = ทุกต้นทางยิงลูกศรออก 1 เส้นพอดี (ปลายทางซ้ำกันได้). one-to-one = ไม่มีปลายทางไหนถูกยิงจาก 2 ต้นทาง. onto = ทุกปลายทางถูกยิงอย่างน้อย 1. bijection = จับคู่หนึ่งต่อหนึ่งครบทั้งสองฝั่ง.

  • ตรวจว่า relation เป็นฟังก์ชันไหม: (1) ทุกตัวใน domain มีคู่? (2) ไม่มีตัวไหนมี 2 คู่? — R = {(a,b),(b,c),(c,f),(b,a)} ไม่ใช่ (b มี 2 คู่; a,d,e,f ไม่มีคู่). R⁻¹ ของ non-function อาจเป็น function ได้ เช่น R={(a,a),(a,b)} → R⁻¹={(a,a),(b,a)} เป็น A→A (ชุด 4 ข้อ 7.4/8.4)
  • จำนวนฟังก์ชัน A → B = |B||A|: {0,1,2}→{1} มี 1 ตัว · {0,1,2}→∅ มี 0 ตัว (ต้องมีคู่ของ 0 แต่ไม่มีอะไรให้จับ) · ∅→B มี 1 ตัว (ฟังก์ชันว่าง) (ชุด 4 ข้อ 5.3/5.4)
  • อ่าน domain/co-domain ให้ดี — คำตอบเปลี่ยนตามนั้น: f : ℕ → Σ* (decimal) one-to-one ✓ onto ✗ (ไม่มี n ที่ f(n) = 001 หรือ e) (ชุด 1 ข้อ 4); f : {0}∪{1}Σ* → ℕ (binary ไม่มี 0 นำ) เป็น bijection ✓ (ชุด 2 ข้อ 4); L : regex → R (regular languages) onto ✓ one-to-one ✗ (L(a*) = L((a*)*)) (ชุด 3 ข้อ 4); L : regex → 2Σ* ไม่ onto (ภาษาที่ไม่ regular ไม่มี regex) (ชุด 4 ข้อ 10)
  • "f ⊆ Σ* × ℕ" จริง เพราะฟังก์ชันคือเซตของคู่อันดับ
กับดัก: "ℕ กับ Σ* equinumerous?" เป็นคนละคำถามกับ "f เป็น bijection?" — equinumerous ถามว่ามี bijection สักตัวไหม (มี เพราะ Σ* นับได้) ไม่ใช่ถามถึง f ที่โจทย์ให้.

6. Regular expression และ regular language

นิยาม regex บน Σ (แบบ inductive): ∅ และ a (ทุก a ∈ Σ) เป็น regex; ถ้า α, β เป็น regex แล้ว (αβ), (α ∪ β), α* เป็น regex — และไม่มีอย่างอื่น. (e ไม่ต้องใส่แยก เพราะ e = ∅*.) ความหมาย: L(∅) = ∅, L(a) = {a}, L(αβ) = L(α)L(β), L(α∪β) = L(α) ∪ L(β), L(α*) = L(α)*. ลำดับความสำคัญ: * ก่อน, แล้ว concat, แล้ว ∪ — star จับเฉพาะสิ่งที่ติดซ้ายมือ (ab* = a(b*), (ab)* ต่างกัน).
นิยาม regular language — 2 แบบที่เทียบเท่ากัน (ชุด 1 ข้อ 9):
(1) L regular ⇔ มี regex α ที่ L(α) = L
(2) เซตของ regular languages = เซตเล็กที่สุดที่มี ∅, {a} (ทุก a ∈ Σ) และปิดภายใต้ ∪, concatenation, * (ถ้า L₁, L₂ อยู่ในเซต L₁∪L₂, L₁L₂, L₁* ก็อยู่)
(3) (บทที่ 2) L regular ⇔ มี finite automaton ที่ accept L

วิธีอ่าน regex: จากนอกสุดเข้าใน — ท้ายสุดมี * ไหม → star ของข้างใน; มี ∪ นอกวงเล็บไหม → union; ไม่งั้น concat. วิธีเช็ค string: ตัด string จากซ้ายไปขวาตามชิ้นของ regex ให้หมดพอดี; X* = วางก้อน X ต่อกัน 0,1,2,… ก้อน (ก้อนต้องเหมือน X เป๊ะ). ตัวอย่าง: aaaaabbbbb ∉ a(ab)* (หลัง a ต้องเป็นก้อน ab แต่เจอ aa) แต่ ∈ aΣ* (Σ* = อะไรก็ได้).

7. Deterministic Finite Automaton (DFA)

นิยาม DFA M = (K, Σ, δ, s, F): K เซตจำกัดของ state, Σ alphabet, δ : K × Σ → K transition function (ทุกคู่ (q,a) มีปลายทางเดียว), s ∈ K start state, F ⊆ K เซตของ final (accepting) states. configuration = (q, w) (state ปัจจุบัน, input ที่ยังไม่อ่าน). yield in one step: (q, aw) ⊢M (q′, w) ⇔ δ(q,a) = q′. ⊢* = หลายก้อน (รวม 0). M accepts w ⇔ (s, w) ⊢* (q, e) โดย q ∈ F. L(M) = {w | M accepts w}.

วิธีอ่านรูป: ▷ ชี้ start · วงคู่ = final · ลูกศร q ─a→ q′ คือ δ(q,a) = q′. เขียน δ แบบ enumerate: {((q0,a),q0), ((q0,b),q1), …} หรือ {(q0,a,q0), …} ต้องมีครบ |K|×|Σ| คู่ (ชุด 1 ข้อ 11a, ชุด 2 ข้อ 9a). เขียน run: (q0, aaab) ⊢ (q0, aab) ⊢ (q0, ab) ⊢ (q0, b) ⊢ (q1, e) — เขียนจนอ่านหมด แล้วสรุป accept/reject จากว่า state สุดท้าย ∈ F ไหม (ชุด 1 ข้อ 11b, ชุด 2 ข้อ 9b, ชุด 4 ข้อ 18: configuration ที่ "yield ได้" ต้องมีทั้ง state และ input ที่เหลือตรงกับการเดินจริง).

  • F เป็นเซต — เขียน F = {q0} ไม่ใช่ F = q0 (ชุด 4 ข้อ 14)
  • e ∈ L(M) ⇔ s ∈ F
  • trap / dead state: state ที่ไม่ final และออกไม่ได้ (วนตัวเองทุกตัวอักษร) ใช้ทำให้ DFA "complete"; DFA ที่บางคู่ (q,a) ไม่มีเส้น = ไม่ complete → string ที่ติดถือว่า reject (ชุด 4 ข้อ 17: q2 ไม่มีเส้นออก)
  • DFA equivalent ⇔ L(M₁) = L(M₂) (รับ string ชุดเดียวกัน) — ไม่เกี่ยวกับจำนวน state หรือชื่อ state (ชุด 4 ข้อ 16)

7.1 วิธีออกแบบ DFA จากภาษา (ข้อวาด — ออกทุกชุด)

  1. แปลโจทย์เป็นภาษาคน: {aba} = string เดียว · {ab}{a}* = ab แล้ว a กี่ตัวก็ได้ · aΣ* = ขึ้นต้น a แล้วอะไรก็ได้ · {ω | เงื่อนไข} = คิดตรง ๆ
  2. ถามว่า "ระหว่างอ่าน string ทีละตัว เครื่องต้องรู้อะไรบ้างถึงจะตัดสินตอนจบได้" — แต่ละคำตอบที่เป็นไปได้ = 1 state (มักเป็นตัวนับ: "b ติดกันท้ายสุด = 0/1/≥2", "ความยาว mod 3 = 0/1/2", "ตรงกับส่วนหัวของ aba ถึงไหน") + 1 state "ผิดทางแล้ว" (trap) ถ้าจำเป็น
  3. ลากเส้น: จากทุก state อ่านทุกตัวอักษร ถาม "ตอนนี้รู้ X แล้วอ่านตัวนี้ → ควรรู้อะไร" → ไป state ที่ตรงกับคำตอบ (DFA ต้องครบทุกคู่)
  4. final = state ที่ "สิ่งที่รู้" ตรงเงื่อนไขของภาษา; start = สิ่งที่รู้ก่อนอ่านอะไร (เช็คว่า e อยู่ในภาษาไหม → start เป็น final ไหม)
  5. ตรวจ ด้วย string สั้น ๆ ที่ควรรับ 2 ตัว และไม่ควรรับ 2 ตัว (รวม e)

ตัวอย่างละเอียดทุกข้อ (10 เครื่อง พร้อมตารางเหตุผลทุกเส้น) อยู่ในส่วนเฉลย ชุด 1 ข้อ 12–13, ชุด 2 ข้อ 10, ชุด 3 ข้อ 8. ภาษาพิเศษ: {e} = start เป็น final แล้วทุกอย่างตกไป trap · {} = start ไม่ final (ไม่มี final เลย) · complement = ใช้ DFA complete เดิม แล้วสลับ final ↔ non-final.

8. Nondeterministic Finite Automaton (NFA) และการแปลงเป็น DFA

นิยาม NFA M = (K, Σ, Δ, s, F) โดย Δ ⊆ K × (Σ ∪ {e}) × K เป็น relation (เซตของ triple (q, a, q′)): จาก state เดียวกันอ่านตัวอักษรเดียวกันไปได้หลายที่ / ไม่ได้เลย / และมี e-transition (เปลี่ยน state โดยไม่อ่าน input). (q, w) ⊢ (q′, w′) ⇔ w = uw′ โดย (q, u, q′) ∈ Δ, u ∈ Σ ∪ {e}. M accepts w ⇔ มีอย่างน้อยหนึ่ง computation (s, w) ⊢* (q, e), q ∈ F.

ภาษาคน: NFA "เดา" ได้ — string ถูกรับถ้ามีสักทางที่ไปถึง final พร้อมอ่านหมดพอดี; ทางที่ตัน (hang: ไม่มีเส้นให้ไป) หรือจบที่ non-final ไม่ทำให้ reject ตราบใดที่ยังมีทางอื่นสำเร็จ. วิธีเช็ค ω ∈ L(M): วาด computation tree จาก (s, ω) แตกกิ่งทุกทางเลือกรวม e (e ไม่กิน input) จนทุกกิ่ง hang/หมด input; เจอกิ่งจบที่ final พร้อม e → accept (ชุด 3 ข้อ 7). DFA เป็น NFA แบบพิเศษ (Δ ที่เป็นฟังก์ชันไม่มี e) — ทั้งสองมีพลังเท่ากัน (Theorem 2.2.1).

8.1 Powerset (subset) construction — NFA → DFA (ชุด 1 ข้อ 14, ชุด 3 ข้อ 9)

  1. E(q) (e-closure) = เซตของ state ที่ไปถึงจาก q ด้วย e-transition 0 ตัวขึ้นไป (รวม q เอง). คำนวณเป็นรอบจนไม่เพิ่ม
  2. state ของ DFA = subset ของ K (superstate). start ของ DFA q′₀ = E(s)
  3. δ′(Q, a) = ⋃ { E(p) | มี q ∈ Q ที่ (q, a, p) ∈ Δ } — "จากทุก state ใน Q อ่าน a ไปได้ที่ไหนบ้าง แล้วเอา e-closure ของปลายทางมารวมกัน"
  4. ทำแบบ worklist: เริ่มจาก q′₀ คำนวณทุกตัวอักษร ได้ superstate ใหม่ก็เพิ่มแถว จนไม่มีใหม่ (ไม่ต้องทำครบ 2|K|). ∅ (ไม่มี state) เป็น trap ถ้าเกิดขึ้น
  5. F′ = superstate ที่มีสมาชิกใน F (Q ∩ F ≠ ∅)
กับดัก: ลืมรวม E(·) ของปลายทาง (ต้องเป็น ⋃E(p) ไม่ใช่ {p}); ลืม self-loop; คำถามแบบ δ′(δ′(q′₀,a),b) ให้ทำตามสูตรทีละชั้น (อ่าน a แล้ว b).

10. ภาษาที่ไม่ regular: Pigeonhole และ Pumping Theorem

10.1 Pigeonhole บน DFA (ชุด 1 ข้อ 15)

DFA ที่มี n state อ่าน string ยาว ≥ n จะผ่าน state n+1 ตำแหน่ง → ต้องมี state ซ้ำ (pigeonhole: n+1 นก n รัง) → ระหว่างตำแหน่งที่ซ้ำคือ cycle. ผลข้างเคียง: state-transition diagram ของ DFA ใด ๆ มี cycle เสมอ (เดินด้วย aⁿ). เขียนส่ง: "Let n = |K|, a ∈ Σ, q₀ = s, qᵢ₊₁ = δ(qᵢ, a). Among q₀…qn (n+1 states) two coincide by pigeonhole: qᵢ = qⱼ, i < j; the path qᵢ→…→qⱼ is a cycle. ∎" (ต้องอ้างว่า δ เป็นฟังก์ชันจึงเดินได้ตลอด — NFA อาจไม่มี cycle)

10.2 Pumping Theorem (Theorem 2.4.1) และวิธีเขียนพิสูจน์

L regular ⇒ มี n ≥ 1 ที่ทุก w ∈ L, |w| ≥ n เขียนได้เป็น w = xyz โดย y ≠ e, |xy| ≤ n และ xyⁱz ∈ L ทุก i ≥ 0.

ภาษาคน: y คือส่วนที่วน cycle ใน DFA — วนกี่รอบ (i = 0, 1, 2, …) ก็ยังถูกรับ. ใช้ได้เพื่อ "พิสูจน์ว่าไม่ regular" เท่านั้น (ทิศเดียว).

สูตรเขียนพิสูจน์ (ท่องได้เลย):

  1. Suppose L is regular; let n be the pumping constant.
  2. Choose w ∈ L with |w| ≥ n ที่ n ตัวแรกเป็นสัญลักษณ์เดียวกัน (เพื่อบังคับ y): เช่น w = aⁿbⁿ, aⁿbⁿcⁿ, aⁿb2n
  3. Then w = xyz, y ≠ e, |xy| ≤ n → y = aᵏ for some k ≥ 1 (อยู่ใน n ตัวแรก)
  4. Choose i (มัก i = 0 หรือ 2): xy⁰z = an−kbⁿ has fewer a's than b's → ∉ L
  5. Contradiction → L is not regular. ∎

ตัวอย่างในชุดฝึก: aⁿbⁿcⁿ (ชุด 1 ข้อ 16 — เหมือน aⁿbⁿ), {aᵖ | p prime} (i = p+1 ทำให้ |xyⁱz| = p(1+k) ไม่ prime). ใช้ closure ช่วย (ชุด 2 ข้อ 11–12): ถ้าโจทย์เป็นภาษาที่ pump ยาก ให้แปลงด้วย op ที่ regular ปิด: Σ* − {aⁿb2n} regular ⇒ complement คือ {aⁿb2n} regular (ขัดแย้ง); {ap−2} regular ⇒ {ap−2}·{aa} = {aᵖ} regular (ขัดแย้ง). ทิศต้องถูก: "จาก L ที่สมมติว่า regular สร้างภาษาที่รู้ว่าไม่ regular".

กับดัก: ต้องอธิบายว่าทำไม y เป็น a ล้วน (จาก |xy| ≤ n) ห้ามสมมติเอง; ต้องเลือก w ที่ยาว ≥ n โดยใช้ n ของ theorem (ห้ามเลือก n เอง); อย่าใช้ theorem พิสูจน์ว่า regular.

  2. ใช้ fact: union ของเซตนับได้สองเซตนับได้ (สลับ dovetail เหมือนชุด 1 ข้อ 7) → (A − B) ∪ B นับได้

ข้อ 19 8 คะแนนเซตพิสูจน์ / อธิบาย

โจทย์: Prove A ∩ B = A \ B̄.

วิธีคิดทีละขั้น

  1. พิสูจน์เซตเท่ากัน = แสดง ⊆ สองทาง (double inclusion)
  2. (⊆) ให้ x ∈ A ∩ B → x ∈ A และ x ∈ B → x ∉ B̄ → x ∈ A และ x ∉ B̄ → x ∈ A \ B̄
  3. (⊇) ให้ x ∈ A \ B̄ → x ∈ A และ x ∉ B̄ → x ∈ B → x ∈ A ∩ B ∎
  4. ภาพ Venn: "อยู่ใน A ตัดส่วนที่ไม่อยู่ใน B ทิ้ง" = "อยู่ใน A และ B"

เขียนลงกระดาษคำตอบ

(⊆) Let x ∈ A ∩ B. Then x ∈ A and x ∈ B, so x ∉ B̄; hence x ∈ A \ B̄.
(⊇) Let x ∈ A \ B̄. Then x ∈ A and x ∉ B̄, i.e. x ∈ B; hence x ∈ A ∩ B.
Therefore A ∩ B = A \ B̄. ∎

จุดที่มักพลาด

  • ต้องเขียนทั้งสองทิศ — ทิศเดียวได้แค่ ⊆
  • ใช้ x ∉ B̄ ⇔ x ∈ B ให้ชัดเจน (นิยาม complement)

ข้อ 20 9 คะแนนcountabilityพิสูจน์ / อธิบาย

โจทย์: Let Σ be an alphabet and R ⊆ 2Σ* the set of all regular languages. Is R finite or infinite? If infinite, is it countable or uncountable? Prove your answer.

วิธีคิดทีละขั้น

  1. อนันต์: {aⁿ} regular ทุก n และต่างกันหมด (a ∈ Σ)
  2. นับได้: ทุก regular language = L(α) สำหรับ regex α บางตัว; α ∈ Σ′* โดย Σ′ = Σ ∪ {(, ), ∅, ∪, *} จำกัด → regex นับได้ → R (ภาพของฟังก์ชัน L จากเซตนับได้) นับได้
  3. สรุป: R เป็นเซตอนันต์นับได้ (countably infinite)
  4. เทียบ: 2Σ* นับไม่ได้ → ภาษาส่วนใหญ่ไม่ regular — ชุด 2 ข้อ 7 ข้อเดียวกัน

เขียนลงกระดาษคำตอบ

R is infinite: for a ∈ Σ, {aⁿ} ∈ R for every n ∈ ℕ and these are pairwise distinct. R is countable: every L ∈ R equals L(α) for some regular expression α, which is a string over the finite alphabet Σ′ = Σ ∪ {(, ), ∅, ∪, *}. Since Σ′* is countably infinite, so is the set of regular expressions, and L(·) maps it onto R; hence R is countably infinite. ∎
